# 食物链 · 荒野生存博弈

基于《食物链》核心游戏流程与机制 V1.0 实现的中文网页策略游戏：8 种隐藏身份的动物、6 个地区、7 个回合，在痕迹、谎言与稀缺食物之间活下去。单人练习完全在浏览器里运行，也支持最多 8 位真人的联机房间，不足 8 人由电脑补齐。

**在线游玩：[GitHub Pages](https://aidong27.github.io/food-chain-wilds/)** · [原站](https://food-chain-wilds.food-chain-game.workers.dev/)

## 2.2：手机端更顺手

- **操作就在地图下面。** 手机上每个阶段的决定紧接在地图和身份卡下方，常见尺寸的手机不用滚动就能边看地图边操作：
  - 四个行动排成一行；
  - 投放直接点地图；
  - 行动结果出现时自动滚到眼前；
  - 新阶段开始时回到顶部。
- **去掉重复。** 手机上不再重复显示阶段标题，也去掉了和地图重复的六个地区按钮；身份卡压成两行，新手提示移到操作下方。地图上可以前往的相邻地区名字变成琥珀色并带虚线圈；投放前，有食物的地区会轻轻闪动。
- **横屏两栏。** 手机横过来时，地图固定在左边，操作在右边滚动。
- **打字不再拥挤。** 键盘弹出时收起底栏和快捷短语，发送后键盘也不会收回；安卓上整个页面会缩到键盘上方。
- **更好点。** 线索板席位、快捷短语、提示的关闭按钮和标签页都加大了触控范围。触屏上输入框统一用 16px 字号，iOS 不会再自动放大页面。
- **其他。**
  - 对局中下拉不会刷新页面。
  - 提示消息改从屏幕上方出现，不再挡住底部按钮。
  - 首页在手机上更紧凑：「开始单人练习」会停在屏幕底部，直到表单滚到眼前；「继续上次练习」排在表单最前。
  - 终局页把头像和数据压进一屏，不用滚动就能点到按钮。

## 2.1：新手教程与更多反馈

- **新手教程。** 第一次打开页面会询问是否进入教程；通过邀请链接打开时直接进房间，不会弹出。教程是一局真实的单人对局：你是麋鹿，2 号是冒充野兔的灰狼。向导用 23 步带你走完前两夜：
  - 看营地发言，私信试探；
  - 秘密投放，用「警觉」发现天敌并转移；
  - 采食，读夜晚报告；
  - 根据被咬者的指认记下推理。

  每一步只高亮需要看或点的地方，其余操作暂时锁定。第三夜起由你自己决定，这一局可以接着玩完。教程随时可以退出，刷新或下次打开都会从原来的步骤继续；首页和生存手册里也能重新打开。
- **线索板。** 交流阶段列出 8 种动物分别被谁认领。两人认领同一身份时标出「冲突」，冒充已知身份时标出「冒名」。点席位即可查看并记录推理。
- **行动有回音。** 技能、移动、躲藏、尖叫的结果直接显示在行动按钮下方；被咬时屏幕边缘泛红，吃到东西时泛绿。
- **夜晚报告更完整。** 除了你自己的遭遇，还列出：
  - 今夜倒下的居民；
  - 你身边谁进行了进食；
  - 下一夜的食物数量和你的饥饿倒计时。
- **真相回放。** 终局后可以逐夜回看每个人进食时真正站在哪里、谁咬了谁、谁吃到了东西。
- **生存图鉴。** 本机记录对局数、存活次数与最高分。每用一种动物活到第七夜就收录进图鉴，首页的动物卡片会标出收录次数。
- **界面细节。** 只在新一夜开始时出现全屏标题，其余阶段改为不遮挡的小提示；桌面端左栏在 1440×900 下能完整显示 8 位居民。
- **平衡。** 野兔饥饿周期 2→3，模拟存活率从 37% 升到 54%，各身份收敛到 47%–62%。

## 2.0 有什么不同

1.0 能跑通七回合，但单人练习依赖后端、电脑玩家随机行动、各身份存活率从 4% 到 92% 不等。2.0 在保留原设计流程（交流 → 秘密投放 → 行动 → 痕迹 → 通话 → 进食 → 结算）的前提下，做了这些改动：

- **单人练习离线运行。** 规则引擎直接在浏览器里运行，不再连接 Cloudflare：打开页面即可游玩，刷新可继续，后端不可达时也能玩。页面不再引用 Google Fonts。
- **会推理的电脑玩家。** 每个电脑只根据自己能看到的信息（公开投放、身边痕迹、被咬记录、死亡揭晓、对话）维护身份推断，据此投放、追猎或躲避。捕食者会冒充草食动物，被咬的动物会当众指认凶手，死者的身份会揭穿冒名者。你可以私信它们，问身份、去向或怀疑对象。测试会验证电脑的决策不受隐藏信息影响。
- **重新平衡。** 用 2000 局全电脑模拟调整了原文第 20 节留空的数值，各身份存活率收敛到 37%–62%（2.1 进一步收敛到 47%–62%，见下表）。
- **单人练习难度。** 入门 / 标准 / 老练三档，只影响电脑捕食者的精明程度。
- **单人流程更紧凑。** 单人时跳过只对真人有意义的“观察痕迹”“私下通话”两个阶段，痕迹改在获取食物时查看；倒下后可以一键快进到终局。联机时，没有可通话对象的席位会被自动跳过。
- **界面重做（月夜荒野）。** 改用 Preact 组件，并整体重新设计：
  - 地图是主舞台：桌面端一屏放下身份、地图、行动与消息，不再上下滚动；手机端用底部标签栏切换「行动 / 消息 / 居民 / 记录」，主按钮固定在拇指可及处。
  - 统一的线性图标、夜色配色与书法标题字体（自托管的小字集，不请求任何外部字体服务）。
  - 地图标记显示你的动物头像、食物、足迹、遗骸与投放席位；行动阶段高亮可前往的相邻地区。
  - 投放点一下地区即可，锁定前可改；行动、进食都是带说明与消耗的大按钮，捕食目标可直接点选。
  - 消息以气泡按夜分组，私信有单独标记；身份推理用头像选择；每夜有结算报告，新手前两回合有提示。
  - 输入中文时不会被状态刷新打断。
- **代码可维护。** 引擎、电脑、界面、后端拆成带类型的模块，原 18 项规则测试全部保留并扩充到 35 项（2.1 为 40 项）。

## 规则速览

每回合：公共交流 → 秘密投放（全员锁定后公开）→ 2 次行动（移动、躲藏、技能、尖叫各 1 SP）→ 观察痕迹 → 私下通话 → 获取食物 → 饥饿结算。第 7 回合结束时仍存活即获胜。

| 动物 | HP | SP | 饥饿周期 | 食物 | 技能 |
|---|---:|---:|---:|---|---|
| 灰狼 | 5 | 5 | 1 | 捕食鹿、兔、野猪（伤害 2）；食腐 | 嗅觉：当前及相邻地区猎物数量 |
| 赤狐 | 5 | 5 | 3 | 捕食兔、蛇、渡鸦；食腐 | 窃听：读取一条涉及同地区玩家的历史私信 |
| 山猫 | 4 | 4 | 2 | 捕食兔、渡鸦、赤狐 | 蓄势：本回合下次命中伤害 +1 |
| 游蛇 | 3 | 4 | 3 | 捕食兔、渡鸦；有食物的地区捕捉小型猎物 +2 | 伏击：抹除本地痕迹，下次命中 +1 |
| 野兔 | 4 | 5 | 3 | 采食 | 疾跃：跳至相邻地区并抹除两地痕迹 |
| 麋鹿 | 5 | 4 | 2 | 采食 | 警觉：本地区是否有天敌 |
| 野猪 | 4 | 4 | 2 | 采食 | 硬皮：本回合每次受伤 −1（最低 1） |
| 渡鸦 | 3 | 5 | 3 | 食腐 +4 或采食 +2 | 俯瞰：查看任意地区的痕迹 |

与 1.0 相比：灰狼 SP 4→5 并可食腐；赤狐 HP 4→5、饥饿周期 2→3、可捕食渡鸦并可食腐；游蛇饥饿周期 2→3、可捕捉小型猎物；野兔饥饿周期 2→3（2.1）；野猪 HP 5→4。其余规则不变：

- **体力与透支。** 透支先扣 1 HP，SP 恢复到上限一半，再支付本次费用。
- **进食。** 捕食命中、采食都恢复 3 SP（另有标注者除外），食物从不恢复 HP。
- **地图食物。** 各回合依次为 4 / 4 / 3 / 3 / 3 / 2 / 2 份，在四个肥沃地区轮换，每处每回合最多一份。
- **躲藏。** 只抹除痕迹，不能免疫捕食。
- **遗骸。** 保留 2 个回合。
- **饥饿。** 连续未进食达到周期后，每回合扣 1 HP，直到进食才重置。
- **交流额度。** 每回合私信 5 条、公开消息 1 条，每条最多 50 字。
- **积分。** `存活 10 + 剩余 HP×2 + 进食×2 + 捕食命中×3 + 正确推理×2 − 错误推理`，最低 0。

所有数值集中在 `src/game/data.ts`。

### 平衡模拟

`npm run simulate -- 2000`，8 个电脑对局（标准难度）：

| 灰狼 | 赤狐 | 山猫 | 游蛇 | 野兔 | 麋鹿 | 野猪 | 渡鸦 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 54% | 54% | 55% | 47% | 54% | 62% | 58% | 53% |

平均每局 4.4 位存活。游蛇仍是更依赖移动与情报的高难度身份。同样条件下 1.0 的数值为：赤狐 9%、游蛇 2%、野猪 76%；2.0 的野兔为 37%。这是规则健全性检查，真人平衡仍需试玩确认。

## 技术结构

```
src/game/      规则引擎（浏览器、Worker、测试共用）
  data.ts        地图、动物、阶段与全部可调数值
  engine.ts      对局生命周期与指令处理
  rules.ts       行动、技能、进食、死亡等单条规则
  view.ts        逐玩家视图过滤（服务器发送的唯一数据，也是电脑唯一能读的数据）
  commands.ts    不可信输入的校验
  tutorial.ts    新手教程那一局：固定的身份与电脑剧本
  bots/          电脑玩家：knowledge 推断、brain 决策、talk/language 对话
src/client/    本地对局、WebSocket 联机、语音、存储、本机战绩与应用状态
src/ui/        Preact 界面组件；Tutorial.tsx 为教程向导，styles/ 为样式，icons.tsx 为统一图标
src/assets/    自托管的标题字体子集与其许可证
server/        Cloudflare Worker 与 GameRoom Durable Object
tests/         规则、电脑、Pages/CORS 单元测试与联机端到端脚本
scripts/       平衡模拟
```

服务端仍是权威判定：不会发送其他存活玩家的身份、真实位置、HP/SP、秘密选择、电脑的推断或无权查看的私信。每一夜的站位与捕食记录只在终局后公开，用于真相回放；私信始终只给收发双方。

## 开发

```sh
npm ci
npm test              # 规则、电脑与 Pages/CORS 单元测试
npm run simulate      # 平衡模拟，可传局数：npm run simulate -- 2000
npm run build         # 类型检查 + 构建 dist/
npm run preview:worker  # 完整游戏（含联机）在 http://localhost:8787
npm run test:network    # 另开终端，对运行中的 Worker 做三客户端联机检查
npm run format        # Prettier
```

前端热更新可再开一个终端运行 `npm run dev`，Vite 会把 `/api` 与 WebSocket 转发到 8787。网络测试期间不要重建前端或修改后端，Wrangler 热重载会断开测试连接。`GAME_BASE_URL` 指向其他部署，`GAME_ORIGIN=https://aidong27.github.io` 额外检查 Pages 跨域路径。

## 部署

**GitHub Pages（前端）**：`main` 更新后，GitHub Actions 运行测试并部署 `npm run build:pages` 的产物，基路径为 `/food-chain-wilds/`。单人练习只需要这一步。

**Cloudflare Worker（联机后端）**：2.0 的联机协议升级到第 2 版，必须由拥有该 Cloudflare 账号的维护者执行一次：

```sh
npm run deploy
```

部署前，Pages 上的新版会检测到旧后端，提示“联机服务器仍是旧版本”并暂停联机入口；单人练习不受影响。部署后：

- 原站与 Pages 同时切换到新版。
- 仍开着旧页面的玩家会收到“游戏已经更新，请刷新页面”的提示。
- 1.0 时创建的房间会被视为已过期（房间本来只保留 24 小时）。

Worker 名称、`GameRoom` 类名、SQLite 存储表与 `v1` migration 都没有改动，不需要迁移；`wrangler.jsonc` 只精确允许 `https://aidong27.github.io` 跨域，不要改成通配符。

若主要玩家在中国大陆，`*.workers.dev` 常常无法访问：单人练习不受影响，联机则建议为 Worker 绑定自定义域名，并同步修改 `vite.config.ts` 中的后端地址与 `index.html` 的 CSP。

[发布来源与验证记录](docs/DEPLOYMENT.md)保存了 1.0 的公开发布记录与 2.0 的升级说明。没有附加开源许可证。

## 限制

- **语音。** 使用 WebRTC 与公开 STUN，没有 TURN 中继。严格 NAT 下可能连不上，书面消息不受影响。
- **对局保存。** 联机房间 24 小时过期，没有跨设备账号。单人存档只保存在本机浏览器。
- **电脑对话。** 电脑玩家使用规则与模板生成对话，不调用外部大模型，只理解身份、地点、提问与指控这几类简单表达。

地图和动物插画由 ImageGen 为本项目生成，已转为本地 WebP 资源。标题字体是 [马善政楷书（Ma Shan Zheng）](https://github.com/googlefonts/mashanzheng) 的子集，按 SIL Open Font License 1.1 分发（见 `src/assets/fonts/OFL.txt`）；图标来自 [Lucide](https://lucide.dev)（ISC 许可）。

标题字体只收录标题、阶段、地区、动物和电脑名字用到的字。改动这些文字后，用 `npx tsx scripts/brush-glyphs.ts` 列出字表，再按脚本注释里的 `pyftsubset` 命令（Python fonttools）重新生成；缺字时会自动退回系统楷体。
